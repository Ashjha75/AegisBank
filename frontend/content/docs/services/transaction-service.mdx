## Why a SAGA

A transfer touches two accounts, but there is no single database transaction across services. Instead each
step is saved as soon as it happens, and if a later step fails, an earlier one is **undone by a compensating
action** - here, refunding the sender.

## Endpoints

| Method | Path | Does |
| --- | --- | --- |
| POST | `/api/v1/transactions/transfer` | Starts a transfer |
| GET | `/api/v1/transactions/{transactionId}` | One transfer |
| GET | `/api/v1/transactions/account/{accountNumber}/history` | Transfers of an account |
| POST | `/api/v1/transactions/{transactionId}/verify-otp` | Confirms a paused transfer with its 6-digit code |

## Rules worth remembering

- The OTP is stored only as a hash, compared in constant time, and expires.
- Wrong codes are counted; after the limit the transfer is `FLAGGED` and the sender refunded.
- If even the refund fails, the reason says so (`needs manual check`) - money is never silently lost.
